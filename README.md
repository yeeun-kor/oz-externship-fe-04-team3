

## 📖 프로젝트 소개

### 온라인 강의와 스터디 문화를 결합한 IT 학습 플랫폼 📚

온라인 강의 플랫폼은 언제든지 양질의 콘텐츠를 제공한다는 장점이 있으나, 많은 학습자가 강의를 끝까지 수강하지 못하고 중도에 포기하는 문제가 반복적으로 발생하고 있습니다. 이는 학습 진행 상황을 공유하거나 동기부여를 받을 수 있는 구조가 부족하기 때문입니다. 그 결과 학습은 개인의 의지에만 의존하게 되고, 시간이 지날수록 학습 열정이 감소하는 한계를 보입니다.

StudyHub는 이러한 문제 인식에서 출발하여 온라인 강의를 '완주'할 수 있는 환경을 제공하는 것을 목표로 합니다. 이미 검증된 외부 강의 플랫폼의 강의 정보를 기반으로 동일한 강의를 수강하는 학습자들을 연결하고, 스터디 중심의 학습 구조를 기획하였습니다. 이를 통해 혼자 듣는 강의가 아닌, 함께 목표를 공유하며 학습을 지속할 수 있는 경험을 제공하고자 합니다.

주요 서비스로 스터디 모집과 참여를 중심으로 일정 관리, 학습 진행 현황 공유, 스터디 전용 소통 환경을 제공합니다. 사용자는 정해진 일정과 스터디 구성원과의 약속 속에서 학습에 자연스럽게 몰입하게 되며, 학습 동기를 유지할 수 있습니다. StudyHub는 온라인 강의 시장에서 반복되는 수강 실패 경험을 줄이고, 학습자가 목표를 끝까지 달성할 수 있도록 돕는 스터디 중심 학습 플랫폼입니다.

## 📑 프로젝트 규칙

### Branch Strategy

> main / dev 브랜치 기본 생성main과 dev로 직접 push 제한PR 전 최소 1인 이상 승인 필수
> 

### Git Convention

> 적절한 커밋 접두사 작성커밋 메시지 내용 작성내용 뒤에 이슈 (#이슈 번호)와 같이 작성하여 이슈 연결
> 

> 접두사설명
> 
> Feat :새로운 기능 구현
> 
> Fix :버그 수정
> 
> Docs :문서 추가 및 수정
> 
> Refactor :코드 리팩토링 (동작 변경 없음)
> 
> Test :테스트
> 
> Deploy :배포
> 
> Chore :빌드, 환경 설정 기타 작업
> 

### Pull Request

### Title
- 제목은 '[Feat] 홈 페이지 구현'과 같이 작성합니다.

### PR Type
> - [ ]  FEAT: 새로운 기능 구현
> - [ ]  FIX: 버그 수정
> - [ ]  DOCS: 문서 추가 및 수정
> - [ ]  REFACTOR: 코드 리팩토링
> - [ ]  TEST: 테스트 관련
> - [ ]  DEPLOY: 배포 관련
> - [ ]  CHORE: 기타 작업


### Code Convention
> - styled-Component 변수명 S + 변수명 (ex. Swrap)
> - styled-Component는 return문 위에 작성
> - 크게는 styled-Component, 그 안에서 className 사용
> - Event handler 사용 (ex. handle ~)
> - export방식 (ex. export default ~)
> - 화살표 함수 사용

### Communication Rules

> Discord 활용한 정기 회의
> Notion 활용한 데일리 스크럼 및 주간 스프린트 구현
